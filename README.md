# প্রজেক্ট হেলথ

[![Pages](https://github.com/msilabs/project-health-dashboard/actions/workflows/pages.yml/badge.svg)](https://github.com/msilabs/project-health-dashboard/actions/workflows/pages.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

আপনার প্রজেক্টগুলোতে কোন ফ্রেমওয়ার্ক আর কোন সার্ভার সফটওয়্যার কোন ভার্সনে চলছে, আর কোনটার সাপোর্ট কবে শেষ হচ্ছে, তার হিসাব রাখার স্ট্যাটিক ড্যাশবোর্ড। Laravel 11 আর PHP 8.1 যে প্রজেক্টে চলছে, সেটা এখনই আপগ্রেড দরকার কিনা, এক নজরে দেখা যায়।

কোনো লগইন, সার্ভার বা ডেটাবেস নেই। সব ডেটা থাকে ব্যবহারকারীর ব্রাউজারে, আর JSON ফাইলে export ও import করা যায়।

🔗 **লাইভ:** https://msilabs.github.io/project-health-dashboard/

## যা করা যায়

সাইটে চারটা পেজ। বাঁয়ের সাইডবারে মেনু, আর নিচে দুটো বোতাম: **ডেটা** (import, AI দিয়ে বানানো, export) আর **সেটিংস** (থিম, সতর্কতার সীমা)। `⌘K` বা `Ctrl+K` চাপলে দ্রুত খোঁজা খোলে, সেখান থেকে যেকোনো প্রজেক্ট, প্রোডাক্ট বা কাজে যাওয়া যায়।

**ড্যাশবোর্ড**
- অবস্থা অনুযায়ী প্রজেক্টের সংখ্যা: সাপোর্ট শেষ, জরুরি (ডিফল্ট ৯০ দিন), সতর্কতা (ডিফল্ট ৩৬৫ দিন), নিরাপদ, অজানা।
- **করণীয়:** কোন ভার্সনের সাপোর্ট শেষ বা শিগগির শেষ, কোথায় সার্ভারের সাথে টেকের মিল নেই, আর কোন কোন প্রজেক্টে। "এখনই" আর "শিগগির" দুই ভাগে।
- প্রজেক্টে চলা সব ভার্সনের সাপোর্ট টাইমলাইন।
- করণীয়র পাশেই ম্যানেজমেন্ট রিপোর্টের AI প্রম্পট।

**প্রজেক্ট**
- খোঁজা (নাম, দায়িত্বে থাকা মানুষ, ট্যাগ, ভার্সন), অবস্থা আর এনভায়রনমেন্ট দিয়ে ফিল্টার। ক্যাটালগের "কয়টা প্রজেক্ট" লিংকে ক্লিক করলে সেই প্রোডাক্ট বা ভার্সনের প্রজেক্টগুলো আসে। ফিল্টার URL-এ থাকে, তাই লিংক শেয়ার করা যায়।
- সারিতে ক্লিক করলে পাশে প্যানেল খোলে: সমস্যা, টেক ভার্সন, আর প্রতিটা এনভায়রনমেন্টে (production, staging …) সার্ভারের ভার্সন, প্রতিটার সাপোর্ট কবে পর্যন্ত। সেখানেই এডিট, মুছে ফেলা, আর এই প্রজেক্টের আপগ্রেড পরিকল্পনার AI প্রম্পট।
- নতুন প্রজেক্টে লাগে শুধু নাম, টেক আর একটা এনভায়রনমেন্ট। দায়িত্বে, ট্যাগ, রিপো, নোট আর আর্কাইভ থাকে "আরও তথ্য"-এর ভেতরে।
- ক্যাটালগে নেই এমন প্রোডাক্টের নাম লিখলে সারির নিচে "endoflife.date থেকে তারিখ আনুন" আসে; এক ক্লিকে প্রোডাক্টটা ক্যাটালগে যোগ হয়।
- **সামঞ্জস্য:** কোনো টেক ভার্সনের যে রানটাইম লাগে, সার্ভারে তা আছে কিনা। যেমন Laravel 13 চলছে, অথচ production-এ PHP 8.2।
- **অমিল:** একই প্রজেক্টের production আর staging-এ একই প্রোডাক্টের ভিন্ন ভার্সন।
- **শুরু থেকে এখন:** প্রজেক্টের প্যানেলে প্রতিটা অংশের শুরুর আর এখনকার ভার্সন পাশাপাশি দেখায় (যেমন Laravel 9: সাপোর্ট শেষ, Laravel 12: সাপোর্ট আছে), নিচে প্রতিটা ধাপের তারিখ। "সারাংশ কপি" দিয়ে ম্যানেজমেন্টকে পাঠানোর মতো লেখা পাওয়া যায়।
- প্রজেক্ট এডিট করে বা import করে কোনো ভার্সনের সাইকেল বদলালে (যেমন Laravel 11 থেকে 12) ধাপটা নিজে থেকেই ইতিহাসে যোগ হয়। প্যাচ ভার্সনের বদল (12.40 থেকে 12.41) যোগ হয় না। আগের আপগ্রেডগুলো এডিটের "আপগ্রেডের ইতিহাস" অংশে হাতে লেখা যায়। সেভের পর কোন ধাপ যোগ হলো তা জানায়; ভুল ভার্সন ঠিক করছিলেন, আপগ্রেড নয়, এমন হলে সেখান থেকেই "ধাপ বাদ দিন"। নিজে থেকে যোগ হওয়া ধাপে আজকের তারিখ বসে; আপগ্রেড আগে হয়ে থাকলে প্যানেলে ধাপের তারিখে ক্লিক করে বদলানো যায়। ধাপের পাশের × দিয়ে মোছা যায়, আর ফিরিয়ে আনা যায়।

**আপগ্রেড**
- কোন প্রজেক্টে কী আপগ্রেড হয়েছে, আগে থেকে এখন। তারিখ দিয়ে ফিল্টার (থেকে, পর্যন্ত), বা "সব সময়", "এই বছর", "গত ১২ মাস"। ফিল্টার URL-এ থাকে।
- উপরে আগে আর এখনের অবস্থার বার (লাল থেকে সবুজ), আর কয়টা অংশ ঝুঁকি থেকে বেরিয়েছে।
- প্রতিটা প্রজেক্টে অংশ, আগের আর এখনকার ভার্সন সাপোর্টের তারিখসহ, আর ধাপগুলো।
- "প্রিন্ট / PDF": প্রিন্টে সাইডবার আর ফিল্টার বাদ যায়, সবসময় লাইট থিম। প্রিন্টের ঘরে "Save as PDF" বাছলে PDF হয়।

**ক্যাটালগ**
- দুটো ট্যাব: **টেক** (কোডের ফ্রেমওয়ার্ক আর লাইব্রেরি) আর **সার্ভার** (রানটাইম, ডাটাবেস, ক্যাশ, ওয়েব সার্ভার, OS)। শুরুতে শুধু প্রজেক্টে ব্যবহৃত প্রোডাক্টগুলো দেখায়।
- প্রতিটা ভার্সনের সক্রিয় সাপোর্ট আর সিকিউরিটি সাপোর্টের তারিখ, অবস্থা, আর কয়টা প্রজেক্টে চলছে। রিলিজের তারিখ, LTS আর কী লাগে (যেমন `php 8.3-8.5`) রাখা যায়।
- শুরুতেই ৩৩টা প্রোডাক্টের তারিখ থাকে [endoflife.date](https://endoflife.date) থেকে। সাইট নতুন করে প্রকাশ হলে তারিখগুলো নিজে থেকেই হালনাগাদ হয়; হাতেও লেখা যায়।

**ডেটা (সাইডবারে)**
- JSON import (ফাইল বা পেস্ট করা লেখা), বসানোর আগে কী বদলাবে তা দেখে। ডিফল্টে মিলিয়ে নেয়; পুরো বদলে দেওয়া আছে "আরও অপশন"-এ।
- **AI দিয়ে প্রজেক্ট বানানো (API key ছাড়াই):** রিপোর ফাইল বা সার্ভারের কমান্ডের আউটপুট পেস্ট করুন, প্রম্পট কপি করে ChatGPT, Claude বা Gemini-তে দিন, উত্তর পেস্ট করুন। আপনার লেখায় নেই এমন ভার্সন AI লিখলে সতর্ক করে।
- JSON export (ব্যাকআপ), CSV export, আর শেষ বড় বদল এক ক্লিকে ফিরিয়ে আনা।
- রিপো, দায়িত্বে থাকা মানুষের নাম আর নোট কখনো কোনো AI প্রম্পটে যায় না।

## প্রতিষ্ঠানে ব্যবহার

তিনভাবে ব্যবহার করা যায়:

1. **সরাসরি লাইভ সাইটে।** প্রথমবার খুললে নমুনা ডেটা দেখাবে। "নমুনা মুছে শুরু করুন" দিয়ে নিজের প্রজেক্ট যোগ করুন। ডেটা থাকে শুধু আপনার ব্রাউজারে, তাই মাঝে মাঝে JSON export করে রাখুন।
2. **টিমে JSON শেয়ার করে।** একজন পুরো ডেটা export করে রিপো, ড্রাইভ বা চ্যাটে রাখবে। বাকিরা সাইডবারের "ডেটা" থেকে import করবে।
3. **fork করে নিজের সাইট বানিয়ে।**
   1. রিপোটা fork করুন।
   2. fork-এর **Settings → Pages → Source** থেকে **GitHub Actions** বাছাই করুন।
   3. `main`-এ push করলে সাইট প্রকাশ হবে `https://<user>.github.io/<repo>/`-এ। base path workflow নিজেই রিপোর নাম থেকে ঠিক করে নেয়।
   4. চাইলে `public/seed/projects.json`-এ নিজেদের প্রজেক্ট রাখুন, আর `"meta": { "sample": false }` দিন। তাহলে নতুন কেউ সাইট খুললে নমুনার বদলে সেটাই দেখবে। `data/site.json`-এ নাম আর লিংক বদলান।

> GitHub Pages-এর সাইট সবাই দেখতে পারে। প্রজেক্টের তালিকা গোপন হলে সেটা `public/seed/`-এ রাখবেন না। শুধু JSON ফাইল শেয়ার করে import করুন।

## চালানো

Node.js ২২ বা নতুন ভার্সন লাগবে। সাইট বানানো হয় [আলো (Alo)](https://github.com/msilabs/alo) দিয়ে।

```bash
npm install
npm run dev
```

তারপর http://localhost:3000 খুলুন।

| কমান্ড | কাজ |
|---|---|
| `npm run dev` | লোকাল সার্ভার চালু করে, ফাইল বদলালে পেজ নিজে থেকে রিলোড হয় |
| `npm run build` | পুরো সাইট `dist/` ফোল্ডারে বানায় |
| `npm test` | হিসাব, ইমপোর্ট আর AI-এর অংশের টেস্ট চালায় (Node-এর নিজস্ব `node:test`) |
| `npm run catalog` | endoflife.date থেকে `public/seed/catalog.json` হালনাগাদ করে |

GitHub Pages-এর মতো সাব-পাথের জন্য বিল্ড করতে: `node alo build --base /project-health-dashboard/`

## ক্যাটালগ হালনাগাদ

`npm run catalog` চালালে `public/seed/catalog.json`-এর প্রতিটা প্রোডাক্টের তারিখ endoflife.date থেকে নতুন করে আসে। যে প্রোডাক্ট বা ভার্সন হাতে যোগ করা, আর যে নোট বা শর্ত লেখা, সেগুলো থেকে যায়। নতুন প্রোডাক্ট যোগ করতে [scripts/update-catalog.mjs](scripts/update-catalog.mjs)-এর `SOURCES`-এ endoflife.date-এর নাম দিন।

Pages-এর workflow প্রতিবার প্রকাশের আগে এই স্ক্রিপ্ট চালায়, আর প্রতি সোমবার নিজে থেকে নতুন করে প্রকাশ করে। তাই প্রকাশিত সাইটের ক্যাটালগ এক সপ্তাহের বেশি পুরনো হয় না, রিপোর ফাইলটা পুরনো থাকলেও।

ব্যবহারকারীর ব্রাউজার পেজ খোলার সময় সাইটের `seed/catalog.json` দেখে। সেটা নতুন হলে তারিখগুলো নিজে থেকে মিলিয়ে নেয়; ব্যবহারকারীর যোগ করা প্রোডাক্ট আর ভার্সন থেকে যায়। এখনই হালনাগাদ চাইলে ক্যাটালগ পেজের "endoflife.date থেকে হালনাগাদ" বোতাম আছে।


- প্রজেক্টের ভার্সনে পুরো নম্বর লেখা যায় (`12.40.1`, `v13.2.0`)। ক্যাটালগের যে সাইকেলের সাথে শুরুটা মেলে (`12`), সেটাই ধরা হয়।
- `securityUntil` না থাকলে `supportUntil` দিয়েই শেষ তারিখ হিসাব হয়। দুটোই না থাকলে `state` ঠিক করে দেয় অবস্থা কী হবে: `supported` মানে সাপোর্ট চলছে, `ended` মানে সাপোর্ট শেষ, খালি থাকলে অজানা।
- কোনো ভার্সন ক্যাটালগের সব ভার্সনের চেয়ে পুরনো হলে, আর সবচেয়ে পুরনো ভার্সনটার সাপোর্টও শেষ হয়ে গিয়ে থাকলে, সেটাকে "সাপোর্ট শেষ" ধরা হয়।
- `lifecycle` হয় `active` নয়তো `archived`। আর্কাইভ করা প্রজেক্ট ড্যাশবোর্ডের হিসাবে ধরা হয় না।
- `schemaVersion` ১-এর ফাইলও import হয়। তখন বাদ পড়া ঘরগুলো (deployment-এর `host` আর `url`, ভার্সনের `note` আর `approx`, প্রোডাক্টের `url`, সেটিংসের `deploymentNames`) নেওয়া হয় না, আর `maintenance` ধাপ `active` হয়ে যায়।
- `history` হলো আপগ্রেডের ধাপ। `where` ফাঁকা থাকলে টেকের ধাপ, নইলে এনভায়রনমেন্টের নাম। পুরনো ফাইলে `history` না থাকলেও import হয়।
- import-এ যেকোনো অংশ বাদ দেওয়া যায়। শুধু `projects` থাকলে শুধু প্রজেক্ট বদলায়। শুধু একটা `[...]` তালিকা দিলে সেটাকে প্রজেক্টের তালিকা ধরা হয়।
