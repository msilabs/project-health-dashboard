# প্রজেক্ট হেলথ

[![Pages](https://github.com/msilabs/project-health-dashboard/actions/workflows/pages.yml/badge.svg)](https://github.com/msilabs/project-health-dashboard/actions/workflows/pages.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

আপনার প্রজেক্টগুলোতে কোন ফ্রেমওয়ার্ক আর কোন সার্ভার সফটওয়্যার কোন ভার্সনে চলছে, আর কোনটার সাপোর্ট কবে শেষ হচ্ছে, তার হিসাব রাখার স্ট্যাটিক ড্যাশবোর্ড। Laravel 11 আর PHP 8.1 যে প্রজেক্টে চলছে, সেটা এখনই আপগ্রেড দরকার কিনা, এক নজরে দেখা যায়।

কোনো লগইন, সার্ভার বা ডেটাবেস নেই। সব ডেটা থাকে ব্যবহারকারীর ব্রাউজারে, আর JSON ফাইলে export ও import করা যায়।

🔗 **লাইভ:** https://msilabs.github.io/project-health-dashboard/

## যা করা যায়

সাইটে তিনটা পেজ। বাঁয়ের সাইডবারে মেনু, ডেটার কাজ (import, export), সেটিংস আর থিম (অটো, লাইট, ডার্ক)। `⌘K` বা `Ctrl+K` চাপলে দ্রুত খোঁজা খোলে, সেখান থেকে যেকোনো প্রজেক্ট, প্রোডাক্ট বা কাজে যাওয়া যায়।

**ড্যাশবোর্ড**
- অবস্থা অনুযায়ী প্রজেক্টের সংখ্যা: সাপোর্ট শেষ, জরুরি (ডিফল্ট ৯০ দিন), সতর্কতা (ডিফল্ট ৩৬৫ দিন), নিরাপদ, অজানা।
- **করণীয়:** কোন ভার্সনের সাপোর্ট শেষ বা শিগগির শেষ, কোথায় সার্ভারের সাথে টেকের মিল নেই, আর কোন কোন প্রজেক্টে। "এখনই" আর "শিগগির" দুই ভাগে।
- ঝুঁকিতে থাকা প্রজেক্ট, আর প্রজেক্টে চলা সব ভার্সনের সাপোর্ট টাইমলাইন।
- এক ক্লিকে ম্যানেজমেন্ট রিপোর্টের AI প্রম্পট।

**প্রজেক্ট**
- খোঁজা, অবস্থা আর environment দিয়ে ফিল্টার। দরকার হলে প্রোডাক্ট, ভার্সন, owner, ট্যাগ আর ধাপ দিয়েও। ফিল্টার URL-এ থাকে, তাই লিংক শেয়ার করা যায়।
- সারিতে ক্লিক করলে পাশে প্যানেল খোলে: সমস্যা, টেক ভার্সন, আর প্রতিটা environment-এ (production, staging …) সার্ভারের ভার্সন, প্রতিটার সাপোর্ট কবে পর্যন্ত। সেখানেই এডিট, মুছে ফেলা, আর এই প্রজেক্টের আপগ্রেড পরিকল্পনার AI প্রম্পট।
- **সামঞ্জস্য:** কোনো টেক ভার্সনের যে রানটাইম লাগে, সার্ভারে তা আছে কিনা। যেমন Laravel 13 চলছে, অথচ production-এ PHP 8.2।
- **অমিল:** একই প্রজেক্টের production আর staging-এ একই প্রোডাক্টের ভিন্ন ভার্সন।

**ক্যাটালগ**
- দুটো ট্যাব: **টেক** (কোডের ফ্রেমওয়ার্ক আর লাইব্রেরি) আর **এনভায়রনমেন্ট** (রানটাইম, ডাটাবেস, ক্যাশ, ওয়েব সার্ভার, OS)।
- প্রতিটা ভার্সনের সক্রিয় সাপোর্ট আর সিকিউরিটি সাপোর্টের তারিখ, অবস্থা, আর কয়টা প্রজেক্টে চলছে। রিলিজের তারিখ, LTS, কী লাগে (যেমন `php 8.3-8.5`) আর নোটও রাখা যায়।
- শুরুতেই ৩৩টা প্রোডাক্টের তারিখ থাকে [endoflife.date](https://endoflife.date) থেকে। এক ক্লিকে সব হালনাগাদ হয়; হাতেও লেখা যায়।

**ডেটা (সাইডবারে)**
- JSON import (ফাইল বা পেস্ট করা লেখা), মিলিয়ে নেওয়া বা পুরো বদলে দেওয়া, বসানোর আগে কী বদলাবে তা দেখে।
- **AI দিয়ে প্রজেক্ট বানানো (API key ছাড়াই):** রিপোর ফাইল বা সার্ভারের কমান্ডের আউটপুট পেস্ট করুন, প্রম্পট কপি করে ChatGPT, Claude বা Gemini-তে দিন, উত্তর পেস্ট করুন। আপনার লেখায় নেই এমন ভার্সন AI লিখলে সতর্ক করে।
- JSON export (ব্যাকআপ), CSV export, সেটিংস, আর শেষ বড় বদল এক ক্লিকে ফিরিয়ে আনা।
- URL, হোস্ট, রিপো, owner আর নোট কখনো কোনো AI প্রম্পটে যায় না।

## প্রতিষ্ঠানে ব্যবহার

তিনভাবে ব্যবহার করা যায়:

1. **সরাসরি লাইভ সাইটে।** প্রথমবার খুললে নমুনা ডেটা দেখাবে। "নমুনা মুছে শুরু করুন" দিয়ে নিজের প্রজেক্ট যোগ করুন। ডেটা থাকে শুধু আপনার ব্রাউজারে, তাই মাঝে মাঝে JSON export করে রাখুন।
2. **টিমে JSON শেয়ার করে।** একজন পুরো ডেটা export করে রিপো, ড্রাইভ বা চ্যাটে রাখবে। বাকিরা সাইডবারের "JSON import" থেকে import করবে।
3. **fork করে নিজের সাইট বানিয়ে।**
   1. রিপোটা fork করুন।
   2. fork-এর **Settings → Pages → Source** থেকে **GitHub Actions** বাছাই করুন।
   3. `main`-এ push করলে সাইট প্রকাশ হবে `https://<user>.github.io/<repo>/`-এ। base path workflow নিজেই রিপোর নাম থেকে ঠিক করে নেয়।
   4. চাইলে `public/seed/projects.json`-এ নিজেদের প্রজেক্ট রাখুন, আর `"meta": { "sample": false }` দিন। তাহলে নতুন কেউ সাইট খুললে নমুনার বদলে সেটাই দেখবে। `data/site.json`-এ নাম আর লিংক বদলান।

> GitHub Pages-এর সাইট সবাই দেখতে পারে। প্রজেক্টের তালিকা গোপন হলে সেটা `public/seed/`-এ রাখবেন না। শুধু JSON ফাইল শেয়ার করে import করুন।

## চালানো

Node.js ২২ বা নতুন ভার্সন লাগবে। সাইট বানানো হয় [আলো (Alo)](https://github.com/msilabs/alo) দিয়ে।

```bash
npm install
npm run dev
```

তারপর http://localhost:3000 খুলুন।

| কমান্ড | কাজ |
|---|---|
| `npm run dev` | লোকাল সার্ভার চালু করে, ফাইল বদলালে পেজ নিজে থেকে রিলোড হয় |
| `npm run build` | পুরো সাইট `dist/` ফোল্ডারে বানায় |
| `npm test` | হিসাব, ইমপোর্ট আর AI-এর অংশের টেস্ট চালায় (Node-এর নিজস্ব `node:test`) |
| `npm run catalog` | endoflife.date থেকে `public/seed/catalog.json` হালনাগাদ করে |

GitHub Pages-এর মতো সাব-পাথের জন্য বিল্ড করতে: `node alo build --base /project-health-dashboard/`

## ক্যাটালগ হালনাগাদ

`npm run catalog` চালালে `public/seed/catalog.json`-এর প্রতিটা প্রোডাক্টের তারিখ endoflife.date থেকে নতুন করে আসে। যে প্রোডাক্ট বা ভার্সন হাতে যোগ করা, আর যে নোট বা শর্ত লেখা, সেগুলো থেকে যায়। নতুন প্রোডাক্ট যোগ করতে [scripts/update-catalog.mjs](scripts/update-catalog.mjs)-এর `SOURCES`-এ endoflife.date-এর নাম দিন।

ব্যবহারকারীর ব্রাউজারের ক্যাটালগ নিজে থেকে বদলায় না। ক্যাটালগ পেজের "endoflife.date থেকে হালনাগাদ" বোতাম দিয়ে নিতে হয়।

## JSON ফরম্যাট

```json
{
    "app": "project-health",
    "schemaVersion": 1,
    "settings": { "redDays": 90, "yellowDays": 365, "deploymentNames": ["production", "staging", "development"] },
    "catalog": {
        "tech": [
            {
                "id": "laravel",
                "name": "Laravel",
                "category": "framework",
                "eolSlug": "laravel",
                "url": "https://endoflife.date/laravel",
                "versions": [
                    {
                        "version": "13",
                        "released": "2026-03-17",
                        "supportUntil": "2027-09-30",
                        "securityUntil": "2028-03-17",
                        "lts": false,
                        "state": "",
                        "approx": false,
                        "requires": [{ "product": "php", "min": "8.3", "max": "8.5" }],
                        "note": ""
                    }
                ]
            }
        ],
        "env": [{ "id": "php", "name": "PHP", "category": "runtime", "versions": [] }]
    },
    "projects": [
        {
            "id": "shop",
            "name": "ই-কমার্স স্টোর",
            "repo": "https://github.com/example-org/shop",
            "owner": "রাহিম",
            "tags": ["client"],
            "lifecycle": "active",
            "note": "",
            "tech": [{ "product": "laravel", "version": "12.40" }],
            "deployments": [
                { "name": "production", "url": "", "host": "", "stack": [{ "product": "php", "version": "8.2.28" }] }
            ]
        }
    ]
}
```

- প্রজেক্টের ভার্সনে পুরো নম্বর লেখা যায় (`12.40.1`, `v13.2.0`)। ক্যাটালগের যে সাইকেলের সাথে শুরুটা মেলে (`12`), সেটাই ধরা হয়।
- `securityUntil` না থাকলে `supportUntil` দিয়েই শেষ তারিখ হিসাব হয়। দুটোই না থাকলে `state` ঠিক করে দেয় অবস্থা কী হবে: `supported` মানে সাপোর্ট চলছে, `ended` মানে সাপোর্ট শেষ, খালি থাকলে অজানা।
- কোনো ভার্সন ক্যাটালগের সব ভার্সনের চেয়ে পুরনো হলে, আর সবচেয়ে পুরনো ভার্সনটার সাপোর্টও শেষ হয়ে গিয়ে থাকলে, সেটাকে "সাপোর্ট শেষ" ধরা হয়।
- import-এ যেকোনো অংশ বাদ দেওয়া যায়। শুধু `projects` থাকলে শুধু প্রজেক্ট বদলায়। শুধু একটা `[...]` তালিকা দিলে সেটাকে প্রজেক্টের তালিকা ধরা হয়।

## কাঠামো

```
pages/                    ড্যাশবোর্ড (/), প্রজেক্ট, ক্যাটালগ
components/
  Sidebar, Icon           সাইডবার (মেনু, ডেটা, থিম), SVG আইকন
  QuickSearch             ⌘K দিয়ে দ্রুত খোঁজা
  ProjectDrawer           প্রজেক্ট দেখার আর এডিটের পাশের প্যানেল (সব পেজে)
  ImportDialog            JSON import আর AI দিয়ে প্রজেক্ট বানানো
  SettingsDialog          সেটিংস আর নতুন করে শুরু
  PromptDialog            আপগ্রেড পরিকল্পনা আর রিপোর্টের AI প্রম্পট
global/
  10-core.js              তারিখ, ভার্সন তুলনা, escape
  20-schema.js            ডেটার কাঠামো, normalize, merge, diff
  25-eol.js               endoflife.date-এর ডেটা থেকে ক্যাটালগ
  30-store.js             localStorage, শুরুর ডেটা, undo, ট্যাব sync
  40-analysis.js          অবস্থা, সামঞ্জস্য, অমিল, করণীয়
  50-ui.js                আইকন, ব্যাজ, টোস্ট, ফাইল, CSV, layout
  60-ai.js                AI-এর প্রম্পট আর উত্তর পড়া
  *.css                   ডিজাইন টোকেন আর UI
public/seed/              প্রথমবার খুললে যে ক্যাটালগ আর প্রজেক্ট আসে
scripts/update-catalog.mjs  ক্যাটালগ হালনাগাদের স্ক্রিপ্ট
tests/                    node:test
```

Alo শুধু পেজের কাঠামো বানায়। ডেটা ব্রাউজারে থাকে বলে তালিকা, ফিল্টার আর হিসাব চলে সাধারণ JS-এ (`global/` আর component-এর `<script>`)। AI দিয়ে কোড লেখালে আগে [AGENTS.md](AGENTS.md) পড়িয়ে নিন।

## প্রাইভেসি

- কোনো সার্ভার, ট্র্যাকিং বা analytics নেই। ডেটা আর থিমের পছন্দ থাকে ব্রাউজারের `localStorage`-এ।
- বাইরের যে সার্ভিসের সাথে যোগাযোগ হয়: Google Fonts (ফন্ট), আর endoflife.date (শুধু হালনাগাদ বা "তারিখ আনুন" বোতাম চাপলে)।
- AI-এর প্রম্পট শুধু কপি হয়। এই সাইট নিজে কোনো AI সার্ভিসে কিছু পাঠায় না।
